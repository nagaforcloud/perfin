## What Perfin does

Perfin is a single-player-ready (and SaaS-ready) personal-finance app built end-to-end in TypeScript. It does six things, all of which work together:

1. **Ingest** transactions from CSV / Excel / PDF uploads, **Plaid** bank connections (US/EU/IN/CA), or **Postmark** inbound bank-alert emails.
2. **Categorize** every transaction — rules engine first (instant, transparent, 57 seed rules), Claude Haiku 4.5 fallback for anything the rules can't decide.
3. **Detect** recurring payments (merchant clustering + amount tolerance + cadence classification) and anomalies (large amount, category outlier, rare merchant).
4. **Surface insights** — bento Home dashboard, Insights feed (anomalies / recurring / trends), Inbox queue for things needing review, monthly narrative generated by Claude Sonnet 4.6.
5. **Answer questions** — `/app/ask` is a streaming chat with Claude using nine tools over the ledger. Read tools execute immediately; write tools (`transaction.update`, `transaction.split`, `budget.upsert`, `goal.create`) return *proposals* for your one-click confirmation. Every confirmed agent action is logged.
6. **Bill, install, notify** — Stripe Plus/Pro tiers with feature gates, full PWA (manifest + service worker, installable from any browser), and Web Push notifications opt-in for budget breaches and high-confidence anomalies.

It is, deliberately, **not** a flashy fintech with locked-in proprietary categorization. The schema is open, the categorization rules are JSON, the agent's tool calls and writes are visible and auditable, and you can run the whole thing locally on your laptop with Docker + an Anthropic API key.

```
              │                                       │                                   │

    │  • 3 migrations     │              │  • recurring/anomaly   │
    └─────────────────────┘              │  • Plaid sync (cron)   │         ┌──────────────────────┐
                                         │  • Postmark inbound    │ ◄────── │  Plaid (Sandbox)     │
                                         │  • Stripe webhooks     │         └──────────────────────┘
                                         │  • Web Push fan-out    │
                                         └────────────────────────┘         ┌──────────────────────┐
                                                                            │  Postmark (inbound)  │
                                                                            └──────────────────────┘
                                                                            ┌──────────────────────┐
                                                                            │  Stripe (Checkout +  │
                                                                            │  Customer Portal)    │
                                                                            └──────────────────────┘
```

**Two long-running processes, one database.** The web app handles user-facing requests and short-lived API calls. The worker handles anything long-running or async: file extraction, scheduled Plaid syncs, webhook ingestion, push fan-out. They communicate via HMAC-signed POSTs (web → worker) and webhooks (Plaid / Postmark / Stripe → worker). Both share the same Postgres via Drizzle ORM.

## Quick start

You need: **macOS or Linux**, **Node ≥ 20.11**, **pnpm ≥ 9**, **Docker Desktop** (or any local Postgres).

```bash
# 1. Clone
git clone https://github.com/nagaforcloud/perfin.git
cd perfin

# 2. Install everything (workspaces)
pnpm install

# 3. Bring up Postgres on port 5433
docker compose up -d

# 4. Apply migrations
DATABASE_URL=postgres://perfin:perfin@localhost:5433/perfin pnpm db:migrate

# 5. Configure env
cp .env.example .env
# (edit .env — at minimum set AUTH_SECRET; everything else has dev defaults or is optional)

# 6. Run both apps in parallel
pnpm dev
```

That gives you:
- **http://localhost:3000** — the web app (marketing + app)
- **http://localhost:8001** — the worker API (`/health` returns 200)

Sign up at `/signup`, complete the 3-step onboarding (Welcome → Currency → Connect), drop a CSV at `/app/upload`, and you'll land on `/app/transactions` with categorized rows.

To see the AI features in action, set `ANTHROPIC_API_KEY` in `.env` and restart `pnpm dev`. Then visit `/app/ask`.

## Configuration

Environment variables live in `.env` (gitignored). `.env.example` documents every key.

### Always required

| Var | Purpose | Default |
|---|---|---|
| `DATABASE_URL` | Postgres connection string | `postgres://perfin:perfin@localhost:5433/perfin` |
| `AUTH_SECRET` | Auth.js JWT signing key — **rotate for prod** | dev-only placeholder |
| `AUTH_URL` | Public origin of the web app | `http://localhost:3000` |
| `WORKER_HMAC_SECRET` | HMAC for web → worker calls — **rotate for prod** | dev-only placeholder |
| `WORKER_URL` | Worker base URL (server-side) | `http://localhost:8001` |
| `NEXT_PUBLIC_WORKER_URL` | Worker base URL (browser SSE) | `http://localhost:8001` |
| `NEXT_PUBLIC_APP_URL` | Public origin of the web app (browser side) | `http://localhost:3000` |

### Optional (feature-gated)

| Var | Enables | Notes |
|---|---|---|
| `ANTHROPIC_API_KEY` | Claude categorization (Haiku 4.5) + chat (Sonnet 4.6) + monthly narrative | Without this, categorization falls back to rules-only and chat returns 500. |
| `KMS_KEY` | Encrypted storage of Plaid access tokens (32 bytes / 64 hex) | Required for Plaid. Generate: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `PLAID_CLIENT_ID`, `PLAID_SECRET`, `PLAID_ENV` | Bank connections via Plaid Link | `PLAID_ENV` ∈ `sandbox` / `development` / `production`. Sandbox is free; production requires Plaid review. |
| `PLAID_WEBHOOK_URL` | Where Plaid sends sync events | Default `http://localhost:8001/webhooks/plaid`. For prod, expose via Cloudflare Tunnel / ngrok. |
| `POSTMARK_INBOUND_USER`, `POSTMARK_INBOUND_PASS` | Basic-Auth verify for inbound email webhooks | Leave empty in dev to bypass. |
| `EMAIL_DOMAIN`, `EMAIL_HASH_SECRET` | Per-user inbound address (`u_<hash>@<domain>`) | Default `in.perfin.app`. Rotate `EMAIL_HASH_SECRET` like an API key. |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICE_PLUS`, `STRIPE_PRICE_PRO` | Plus/Pro upgrade flow + webhook upserts | Use Stripe **test mode** in dev. |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_SUBJECT` | Web Push notifications | Generate: `node -e "console.log(require('web-push').generateVAPIDKeys())"` |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Google OAuth login | Optional; credentials login works without it. |
| `CRON_DISABLED` | Disable nightly insights regen + hourly Plaid sync | Set to `1` in tests. |
| `CRON_NIGHTLY`, `CRON_HOURLY` | Override cron schedules | Defaults: `0 2 * * *` and `0 * * * *`. |

Any variable consumed inside a Turbo task must also be listed in `turbo.json` `globalEnv` for caching to work correctly.

## Development

```bash
# Run both apps with hot reload
pnpm dev

# Run a single workspace
pnpm --filter @perfin/web dev
pnpm --filter @perfin/worker dev

# Typecheck the whole repo
pnpm typecheck

# Run all tests
pnpm test

# Run a single workspace's tests
pnpm --filter @perfin/core test

# Production build
pnpm build

# Lint
pnpm lint
```

**Build cache:** Turbo caches successful tasks. The first `pnpm typecheck` after a clean checkout takes ~15s; subsequent runs hit cache and finish in <1s. To force a clean run, delete `.turbo/` and `node_modules/.cache/`.

**Hot reload across workspaces:** Edits to `packages/*` propagate to `apps/*` via the `workspace:*` link, but you may need to restart the worker (`pnpm --filter @perfin/worker dev`) for some package changes to be picked up by `tsx watch`.

## Database

Postgres 16 via Drizzle ORM. Schema lives in `packages/db/src/schema/`, migrations in `packages/db/migrations/` (generated by `drizzle-kit`).

```bash
# Apply pending migrations
pnpm db:migrate

# Generate a migration after editing schema files
pnpm db:generate

# Open Drizzle Studio (browser UI)
pnpm db:studio
```

### Tables (17)

| Table | Purpose |
|---|---|
| `users` | Email/password + plan + Stripe customer id |
| `sessions` | Auth.js session tokens |
| `connections` | Plaid items + manual / email / file-source provenance; encrypted access tokens |
| `accounts` | Bank accounts (manual or linked from a connection) |
| `transactions` | The ledger: cents-as-integer, dedupe-unique, optional parent for splits |
| `budgets` | Per-category spend caps |
| `goals` | Savings goals with deadline + target |
| `category_rules` | User-editable rule overrides (priority + match-type + pattern) |
| `recurring_series` | Detected subscriptions/bills (merchant + cadence + confidence) |
| `anomalies` | Flagged transactions (kind + score + reason) |
| `insights` | AI-surfaced cards (anomaly / recurring / drift / narrative) |
| `agent_actions` | Audit log of every confirmed agent write |
| `agent_proposals` | Pending/confirmed/cancelled agent write proposals |
| `chat_threads`, `chat_messages` | Persisted Ask conversations |
| `inbound_emails` | Postmark webhook log |
| `upload_jobs` | File upload pipeline status + progress |
| `subscriptions` | Stripe subscription mirror |
| `push_subscriptions` | Web Push endpoints |

### Importing the legacy SQLite ledger

If you previously ran the Python prototype (`_legacy/ai_accountant/`), one-shot import its data:

```bash
DATABASE_URL=postgres://perfin:perfin@localhost:5433/perfin \
SQLITE_PATH=./_legacy/ai_accountant/database/ledger.db \
USER_EMAIL=you@example.com \
pnpm --filter @perfin/scripts import-sqlite
```

The script is idempotent — re-running it is safe; existing rows are skipped via the dedupe constraint.

## Optional integrations

Each integration is independent. Skip the ones you don't need; the relevant feature degrades gracefully.

### Anthropic Claude (AI)

Get an API key at <https://console.anthropic.com>. Set `ANTHROPIC_API_KEY` in `.env`.

- **Categorization** uses Claude Haiku 4.5 (cheap; ~$0.001 / 100 transactions).
- **Chat** (`/app/ask`) uses Claude Sonnet 4.6 with prompt caching. ~$0.005 per turn after the first.
- **Monthly narrative** uses Sonnet 4.6, one short generation per user per month.

Without an API key, the rules engine still categorizes ~70% of common transactions, anything unmatched lands as "Needs Review", chat returns a 500 error, and the narrative is skipped.

### Plaid (bank connections)

1. Create a Plaid account at <https://dashboard.plaid.com>. Sandbox is free.
2. Set `PLAID_CLIENT_ID`, `PLAID_SECRET`, `PLAID_ENV=sandbox` in `.env`.
3. Generate `KMS_KEY`: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`.
4. (Optional) Expose `/webhooks/plaid` for sandbox testing via Cloudflare Tunnel:
   ```bash
   cloudflared tunnel --url http://localhost:8001
   # Then set PLAID_WEBHOOK_URL to the tunnel URL + /webhooks/plaid
   ```

In sandbox, log in as `user_good` / `pass_good` to test the full flow. Production access requires a Plaid review (typically 4-8 weeks); ship on sandbox until then.

### Postmark (email forwarding)

1. Create a Postmark account at <https://postmarkapp.com>.
2. Configure inbound email at a domain you own (e.g. `in.perfin.app`). Point the inbound webhook to `https://<your-public-worker>/webhooks/postmark`.
3. Set Basic Auth credentials in Postmark and mirror them to `.env`: `POSTMARK_INBOUND_USER`, `POSTMARK_INBOUND_PASS`.
4. Set `EMAIL_DOMAIN` to your inbound domain and rotate `EMAIL_HASH_SECRET`.

Each user sees their unique address `u_<hash>@<EMAIL_DOMAIN>` on `/app/accounts → Email forwarding`. v1 ships HDFC + ICICI parsers; add more in `packages/connectors/src/postmark/parse.ts` (regex-first; LLM fallback can be added in a future revision).

### Stripe (billing)

1. Create products + prices in the Stripe dashboard for your Plus and Pro tiers.
2. Set in `.env`:
   ```
   STRIPE_SECRET_KEY=sk_test_...
   STRIPE_WEBHOOK_SECRET=whsec_...
   STRIPE_PRICE_PLUS=price_...
   STRIPE_PRICE_PRO=price_...
   ```
3. Forward webhooks locally with the Stripe CLI:
   ```bash
   stripe login
   stripe listen --forward-to http://localhost:8001/webhooks/stripe
   # copy the printed whsec_... into STRIPE_WEBHOOK_SECRET
   ```
4. Test the upgrade flow: sign up, visit `/pricing`, click **Upgrade to Plus**, complete Checkout with card `4242 4242 4242 4242`. The webhook upserts a `subscriptions` row and sets `users.plan='plus'`.

Plan-gated features:
- **Free** — manual upload, basic categorization, 30 agent msgs/mo
- **Plus** — Plaid + email forwarding + unlimited transactions + Excel export + 200 agent msgs/mo
- **Pro** — multi-account Plaid + unlimited agent + members (RBAC) + PDF reports + priority support

The `<PlanGate feature="...">` component renders an upgrade CTA when the current user lacks the feature.

### Web Push (PWA notifications)

1. Generate VAPID keys (one-time):
   ```bash
   node -e "console.log(require('web-push').generateVAPIDKeys())"
   ```
2. Set `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` in `.env`. Mirror the public key to `NEXT_PUBLIC_VAPID_PUBLIC_KEY`. Set `VAPID_SUBJECT=mailto:you@yourdomain`.
3. Open the app, visit `/app/settings/notifications`, click **Enable notifications**, grant permission.
4. Test from the dev console: `fetch('/api/test-push', { method: 'POST' })`.

The service worker is at `apps/web/public/sw.js` and is registered automatically by the layout. PWA install works on Chrome/Edge (any platform), Safari (macOS/iOS), and Firefox (limited).

## Deployment

Perfin ships as two services + a database. The recommended setup:

| Component | Recommended host | Why |
|---|---|---|
| `apps/web` (Next.js) | **Vercel Pro** | RSC streaming + edge middleware + sane env management |
| `apps/worker` (Fastify) | **Fly.io** (1× shared-cpu-1x) | Long-running process; webhooks + cron survive restarts |
| Postgres | **Neon** or **Supabase** | Serverless Postgres; generous free tier |
| Object storage (uploaded files) | **Cloudflare R2** (when graduating from local disk) | S3-compatible; v1 uses local disk in `data/uploads/` |

Estimated cost at pre-revenue: **~$60–140/month** (Vercel Pro $20 + Fly $5 + Neon $0–19 + R2 ~$1 + Postmark $15 + Anthropic $20–80 + Plaid $0–~$0.30/account/month).

A more detailed deployment guide lives in `docs/superpowers/specs/2026-05-04-perfin-redesign-design.md` (§6.9 Hosting and cost).

### Production checklist

- [ ] Rotate every secret in `.env` (`AUTH_SECRET`, `WORKER_HMAC_SECRET`, `KMS_KEY`, `EMAIL_HASH_SECRET`, VAPID keys).
- [ ] Set `NEXT_PUBLIC_APP_URL` and `AUTH_URL` to your real domain.
- [ ] Switch Stripe + Plaid + Postmark from test to live.
- [ ] Confirm `KMS_KEY` is stored in your secrets manager (rotating it invalidates stored Plaid access tokens — plan a re-link campaign first).
- [ ] Set up monitoring on `/health` (worker) and the Next.js health endpoint.
- [ ] Configure Anthropic spend limits.
- [ ] Verify SOC2 status before flipping `PLAID_ENV` to `production`.

## Contributing

This is a solo project today, but contributions are welcome.

1. Fork the repo.
2. Create a feature branch (`git checkout -b feat/your-thing`).
3. Make changes; run `pnpm typecheck && pnpm test` before pushing.
4. Open a PR. Keep diffs scoped — one logical change per PR.

### Coding standards

- TypeScript strict mode. No `any` outside test mocks. `noUncheckedIndexedAccess` is on.
- Each package's `src/` files own one responsibility; split before they grow past ~150 lines.
- New schema → generate a migration (`pnpm db:generate`), commit it.
- Money is always **cents-as-integer**. Use `centsToRupees` / `rupeesToCents` from `@perfin/core`. Never `Number(x.toFixed(2))`.
- Negative amounts use **U+2212 (`−`)**, not hyphen. `formatCurrency` handles this.
- Tests live next to the code they test; vitest config in each package.

### Adding a new bank parser

For PDFs / emails:
- PDFs: drop a small parser in `packages/extractors/src/banks/<name>.ts` exporting `is<Name>(lines): boolean` + `parse<Name>(lines, fileName): ExtractResult`. Wire into `packages/extractors/src/banks/index.ts`.
- Emails: extend `packages/connectors/src/postmark/parse.ts` with another regex branch keyed on the `from:` domain.

Add a fixture under `data/seeds/` and a test under `packages/{extractors,connectors}/tests/`.

### Adding a new agent tool

1. Create `packages/agent/src/tools/<name>.ts` with a `tool({ description, parameters: zodSchema, execute })` function that takes a `ToolContext`.
2. Register it in `packages/agent/src/tools/registry.ts`.
3. If the tool mutates data, return a `ProposalResult` instead of executing — and add a switch case in `packages/agent/src/execute.ts` for the confirm path.
4. Add a test under `packages/agent/tests/`.

## Troubleshooting

### `pnpm install` fails with peer-dependency warnings

Expected. React 19 vs `react-plaid-link`'s React 18 peer is a known mismatch; functionality is unaffected. The `pnpm.overrides` block in the root `package.json` already pins the one peer that actually matters (`zod-to-json-schema@3.24.5`).

### `pnpm build` fails with "useSearchParams() should be wrapped in a suspense boundary"

The `/app/ask` page already wraps the inner component in `<Suspense>`. If you're seeing this on a page you added, wrap any `useSearchParams()` consumer in `<Suspense fallback={...}>`.

### Postgres on port 5432 conflicts

The bundled Docker setup uses **port 5433** to avoid colliding with a host Postgres. If you've already changed it, just update `DATABASE_URL` in `.env` accordingly.

### Build runs out of disk

Next.js production builds write ~600 MB to `.next/`. Clear before re-building:
```bash
rm -rf apps/web/.next apps/worker/dist .turbo
```

### Plaid Link button shows "Loading…" forever

Likely missing `PLAID_CLIENT_ID` / `PLAID_SECRET`, or your worker can't reach Plaid's API. Check `apps/worker` logs and the browser network tab for the `/api/connections/plaid/link-token` response.

### Stripe webhook returns 401

`STRIPE_WEBHOOK_SECRET` mismatch. With the Stripe CLI: copy the `whsec_...` printed by `stripe listen --forward-to ...` into `.env` and restart the worker.

### Web Push doesn't fire

- Confirm permission was granted (`/app/settings/notifications` should show "Enabled").
- Confirm `NEXT_PUBLIC_VAPID_PUBLIC_KEY` matches `VAPID_PUBLIC_KEY`.
